## 4. 未完成工作清单

### N1 · A3-2 头部 yaw —— 「整体旋转」的正解【P0，最高优先】

- **现状**：`koiSkeleton.js` L437 `spine[0] = r[0]`。`r[0]` 是 trail 首段方向 ≈ **上一帧 vel 方向**；再叠加 `headSegs` 段 `rel=0` 的刚性棍 → 头段方向/航向回归斜率 **0.88~0.92**（4 种子一致），头没有独立 yaw 自由度，航向变多少头就当帧转多少。
- **方案候选**（三个都要先在内存变体里 A/B，再决定落哪个）：
  - **A · 一阶滞后**（推荐先试）：`spine[0] += clamp(angNorm(r[0] - spine[0]) * HEAD_YAW_GAIN, ±HEAD_YAW_MAX)`。起点 `GAIN=0.35` / `MAX=0.12 rad(≈7°)`，让头用 3~4 帧追上轨迹方向。
  - **B · 头段允许微弯**：`jointCapRad(t < HEAD_FRAC)` 从 `0` 提到 `~3°`，让头身过渡连续，避免"刚性棍 + 突然起弯"的折角。
  - **C · A+B 合并**（预期最优）：A 给头部惯性，B 给过渡连续性。
- **可复用现成量**：`headOmega`、`prevHeadR`、`angNorm` 在 `updateSpine` L414–415 已算好，方案 A **零新增状态**。
- **必须加的防护**：断言 `|angNorm(spine[0] - r[0])|` 上限。`body[0]` 仍是路径头点（保长重建起点不动），所以头只是"朝向"偏离、不会脱轨；但偏离过大在急转时会指向路径外侧，可能造成头身交叠。
- **验收**：头段方向/航向回归斜率 **< 0.7**；逃跑触发后 15 帧「尾段变化/累计弦角」比值上升（说明身体在弯而非整体转）；`turnprobe` 卷环守卫不破；`npm test` 7/7；常态 `motiondiag` 九项不变（除头段斜率）。
- **风险**：头部滞后会让"头提前指方向"变成"头落在后面"，观感可能更差；30fps 下单帧 7° 是否跟得上急转需实测。

### N2 · AVOID 后期钩形仍在【P0，体态层可先试便宜方案】

- **现状**：C-bend 脉冲只覆盖入场 9 帧（≈300ms），之后身体重新由 trail 路径历史主导 → 特写仍是单向钩形（`docs/swim-baseline/06-avoid-a3-late-hook.png`）。4 种子中 2 个（777 / 424242）后期拖尾大弯 84~99° 抢走全窗口弯曲峰值，仍滞后航向 233~267ms。
- **方案候选**：
  - **便宜 · 重复小脉冲**（先试）：AVOID 持续期按占空比重复注入 `CSTART_TOTAL≈0.5rad`、间隔 ≈12 帧，替代单次 77°。
  - **彻底 · Plan B 两阶段转向**：改 `updateMotion` / `clampHeading` / trail，让"先弯后弹"由路径层产生。会动路径层，6 个探针基准需重录并标注口径断裂。
- **判据**：全窗口弯曲峰不滞后航向 > 100ms（4 种子全部）。

### N3 · 逃跑摆频倍率未降（2.22~3.28×）【P1】

- **根因**：`swimPhase` 推进在 `koiFish.js`（路径层），本轮零路径影响所以没动，只降了行波**幅值**。
- **方案**：`dφ` 上限钳到 2× 巡航；panic 只放大**幅值**不放大**频率**（幅频解耦，正是报告 S3 的核心动作）。
- **落点**：`koiFish.js` 的 `swimPhase` 推进处 + `beat` 计算。

### N4 · S2 指标体系常驻断言【P1，建议在动路径层之前做】

- **目标**：把 `motiondiag` / `escapediag` 的核心量抽成断言，纳入 `npm test`，防后续改动倒退。
- **建议指标**：尾端摆幅%体长、头段回归斜率、入场 C-bend 峰值、弯曲滞后帧数、持续转弯占比、jerk p95。
- **落点**：新建 `scripts/naturalness.mjs`（纯断言模式，复用两个诊断脚本的插桩逻辑；它们现在是大量文本输出的诊断模式，需要抽公共部分）。
- **注意**：这些是**观感代理指标**，阈值只能宽松（防倒退，不追求"达标"）。设严了会把正常调参卡死。

### N5 · S3 节奏（burst–coast / 加速度驱动 / 速度∝体型）【P2】

- 现状缺陷：永不停（`SPEED_FLOOR`）、相位每帧必推进、`beat` 同时改频率与幅值、**没有滑行段**；巡航速度不随体长缩放，`c/U` 从 0.94（小鱼，理论上无正推力）漂到 3.71（大鱼）、`St` 0.13~0.53，跨体型漂移约 4 倍。
- 目标：`DC < 1` 且有明确滑行帧；`St` 收敛 0.2–0.4 且不随体型漂移；`c/U` 全尺寸 1.1–1.7。
- **前置**：N4 就位，否则改完无法判断是变好还是变坏。
- **会动路径层** → 6 个探针基准需重录 + CHANGELOG 标注「与历史数字不可直接比较」。

### N6 · S4 因果闭环（体态 → 推力 → 位移）【P3】

目标是反转「路径拖着身体」为「身体发力推鱼」。需要 `body` 回写 `vel`，或至少把体态弯曲作为位移的一阶贡献项。爆炸半径最大，**只有在 N1–N5 之后观感仍不达标时才做**。

### N7 · S5 群体 cohesion【P3】

`computeWish` 目前只有 separation + alignment，每条鱼被私有随机锚点拉散，没有成群绕游。补 Reynolds 第三力即可，属低风险增量。

### N8 · 观感遗留（斑纹 / 三维明暗 / 胸鳍可见度）【冻结，暂不重启】

`c9cc80e` 这批观感改动已被用户判定「效果很差」并在 S0 回滚。**明确不在运动学修完之前重启**。判据：高对比高频图案 + 30fps = 时间走样，越调花纹越糟。若将来重启，必须同时把模拟频率提到 60Hz。

### N9 · 提帧率的前置条件（属 S3 范畴）【记录，勿单独做】

`trail` 是定长数组、`resampleBody` 按等弧长重采样 → **帧率翻倍会让每点间距减半、可覆盖弧长减半，身体几何直接坏掉**。提帧率必须同步重标定 `trail` 长度与全部「每帧常量」。这是 S1 当时明确排除的原因，不是遗漏。
