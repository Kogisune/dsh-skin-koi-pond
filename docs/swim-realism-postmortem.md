## 0. 执行摘要

1. **当前 HEAD 正是被判定为失败的那个版本；提交是用户拍板「代码+结论一起提交，明天继续修」，不是误提交。** `c9cc80e` 的说明是「鳍贴图占位符引号 bug + 渲染层观感对齐参考实现」，`CHANGELOG.md` 复审结论写明「其余观感改动均为回退候选、明日修复方向待讨论」。长期记忆里「改动全在工作区未提交」的条目**已过时**（当天日志已记录提交决策与精确回滚范围，见 §5 / §7），回滚应按反向 patch 执行，不涉及改写已推送历史。
2. **重构投入很大，但投入方向偏了。** `v0.1.0..HEAD` 共 18 个提交、29 文件、`+8516 / -1308` 行；其中 11 个 `scripts/*.mjs`（新增约 3.0k 行，6 个纳入 `npm test` 断言）与 10 个新增运行时模块。新增机制绝大多数是**约束类**（关节 cap、跟随速率、最小转弯半径、不倒车 carving、持续盘旋放宽、头段刚性锁定、速度下限），不是**自由度类**（节奏、耦合、反馈、推进）。结果是几何指标全绿、运动自由度被系统性收紧。
3. **三条主因，按影响排序：**
   - **P0 时间基**：`mount(..., {koi:12, fps:30})` 硬 30fps；`loop()` 丢帧不补、相位不累积、所有量按「每帧常量」推进；叠加高对比硬边斑纹与 25× 绘制开销 → 卡顿 + 时间走样。真实 C-start 首次肌肉运动约 15ms，30fps 单帧就 33ms，物理上无法表达。
   - **P0 因果倒置**：真实鱼是「神经/肌肉 → 体波 → 水反作用 → 位移」；本项目是「锚点/避让 → wish → vel → 头部轨迹 → 身体重采样 → 体态（+前馈正弦）」。**体态完全不产生位移**，只是位移的装饰。阶段 2 承诺的「路径从体态涌现」没做，所以「灵动」在架构上不可能出现。
   - **P0 节奏单一**：`swimPhase` 每帧必推进、`SPEED_FLOOR` 保证永不停、`beat` 同时改频率与幅值、**没有滑行（coast）状态**。而 2025 年针对**锦鲤**的实测研究指出：锦鲤主要靠调整「滑行期时长」适应流速，尾幅稳定、频率几乎不变；ABZU 的做法是用**加速度**而非速度驱动摆尾，从而产生「加速时甩尾、随后滑行」的生命感。
4. **一个可量化的结构性缺陷**：巡航速度 `cruise` 是固定像素值（2.2~3.0 px/帧），**不随体长缩放**。按当前常量解析估算，`c/U` 从小于 1 到 3.71、`St` 从 0.13 到 0.53，跨体型漂移约 4 倍；只有中等体型恰好落在理论合理区间。这不是调参问题，是量纲问题。
5. **最贴身的对标其实已经给出答案**：11-11 已分析过的 Lively 壁纸「锦鲤池 Koi Pond」，身体是**独立跟随链**、时间用 `dt` + 自适应降载、摆频 `∝ 1/√L`、有 cohesion 与共享吸引子；本轮「对齐参考实现」只抄了**静态外观**（体型 / 斑纹 / 鳍色 / 描边），**没抄运动架构**。所以越对齐越暴露差异——更清楚的轮廓和更硬的图案把 30fps 与架构缺陷一并放大。详见 §3.2.0。
6. **立刻可做的顺序**：先修时间基与回滚观感改动（否则任何运动学改进都会被 30fps 和走样吃掉）→ 建立可测的自然度指标 → 加节奏 → 再谈因果闭环或真 CPG。对应 Plan A / B / C 见 §5。

## 2. 先把「灵动」拆成可测指标

继续用「感觉」争论会重演 09-07 的误判（用「代码里有某机制」推断「输出更自然」）。下表把目标翻译成可测的量，**观感终判仍以用户目测为准**，指标只用于定位与验收。

| 指标 | 定义 | 真实鱼 / 优秀实现参考 | 当前实现 | 判定 |
| --- | --- | --- | --- | --- |
| 帧时间基 | `dt`、相位按秒累积、掉帧补步/插值 | 固定步长 + 累加器 + 插值（Gaffer）；参考实现 `dt=min(0.05,gap/1000)` + 自适应降载 | 每帧常量、丢帧即变慢 | ✗ |
| `St = fA/U` | 尾拍频率 × 峰峰尾尖位移 / 游速 | **0.2–0.4**（高效推进区） | 随体型 0.13–0.53（解析估算，§4 P1-1） | △ |
| `A* = A/L` | 峰峰尾尖位移 / 体长 | **0.1–0.3**，约 0.2L 常见 | 设计包络约 0.2L，但 CHANGELOG 实测静态帧弦偏差仅 **2–8% 体长**（量纲不同，仅作量级参照） | △ |
| `c/U` | 体波相速度 / 游速 | **>1 才有正推力**；实测鱼 1.1–1.7，净功率最优点 ≈1.2 | 中位 ≈2.1、小鱼 ≈0.94、大鱼 ≈3.71 | ✗ |
| `U/L` | 每秒游过几个体长 | 同种鱼应大体一致；`U ∝ f·L`（St 守恒） | 0.40–1.57 BL/s，随体型 4× 漂移 | ✗ |
| 占空比 `DC = T_burst / T_total` | 一次摆动中主动推进占比 | 锦鲤主要靠**调 coast 时长**调速；存在明确滑行段 | 恒为 1（永不停、每帧必摆） | ✗ |
| 转向三阶段时序 | C-bend → 弹射 → 回直/滑行 | C-start 声音到首次肌肉运动 ≈15ms，轮廓以 5ms 间隔采样 | 先有路径后有身体；C 波以 3 关节/帧传播，35 关节 ≈0.39s 才到尾 | ✗ |
| 相位传播 | 头→尾相位滞后（帧或体长归一） | 由相邻振子耦合涌现 | 全局相位 + 独立一阶滞后；实测尾滞后仅 4 帧，瞬态全身同步 | ✗ |
| 体态→位移反馈 | 体波是否产生推力/航向 | 真实鱼、CPG 机器鱼闭环 | 无（开环） | ✗ |
| 群体组织 | cohesion / 邻近同向率 | Reynolds 三力；fishtank / koi-pond / fish-pond 均含 cohesion | 只有 separation + alignment，且私有锚点拉散 | ✗ |
| 帧预算 | p95 帧耗时 < 帧间隔 | 30fps 预算 33ms | lineTo 2215/帧、bodyPoint 约 2000+ 对象/帧 | ✗ |
| 观感 | 用户目测 | 唯一终判 | 11-11 判定「效果很差」 | ✗ |

> 表中 `St / A* / c/U` 的**理论区间**来自外部文献（§3.1），当前值是按仓库常量做的**解析估算**，不是实机测量；假设与局限见 §7。

### 3.1 理论与工程基准（论文原文 / 摘要 / 权威转录）

| 来源 | 关键结论 | 对本项目的意义 |
| --- | --- | --- |
| Lighthill 细长体理论 / *Undulatory and oscillatory swimming*（JFM 2019 综述） | 行波必须 `c_w > U` 才有正推力；幅值包络应从吻部 0 增到尾最大；为抑制 recoil，运动应集中在后半身且身上要有正/负相位（即 >0.5 波长） | 解释 `WAVE_SPAN 2.8→4.5` 为什么是对的；也说明 `c/U<1` 的小鱼在物理上不成立 |
| *On the rules for aquatic locomotion*, Phys. Rev. Fluids 2, 083102 | `St = fA/U ∈ 0.2–0.4` 且 `A* = A/L ∈ 0.1–0.3` 是高效游动的紧约束；**U 几乎与 f 成正比** | 本项目 `beat` 同时放大频率与幅值、U 又不随 L 变，直接违反该约束 |
| *Review of Fish Swimming Modes for Aquatic Locomotion* (Sfakiotakis et al. 1999) | Lighthill 大振幅细长体理论；效率 `η = 1 − ½(1 − U/V)`，V 为体波相速 | 把 `c/U` 当作可验收指标，而非调参感觉 |
| *Intermittent swimming … robotic fish*, Ocean Engineering 2025（**实验对象就是锦鲤 koi carp**） | 锦鲤主要通过**改变连续摆动之间的滑行期时长（duty cycle）**适应不同流速，**尾幅稳定、频率几乎不调**；间歇游动显著降低能耗 | 与本项目做法正好相反：本项目调频率/幅值、从不滑行。这是「机械感」最直接的物种级证据 |
| Mauthner cell / C-start（ScienceDirect 综述） | 声音到首次可检测肌肉运动 ≈**15ms**；C-bend 轮廓以 **5ms** 间隔采样；一次单侧放电决定逃逸方向 | 30fps（33ms/帧）无法表达真实 C-start；必须靠「姿态预置 + 帧内/多步插值」而非逐帧传播 |
| *Learning swimming escape patterns*, arXiv 2105.00771 | 定义 `DC = T_burst/T_total`；高雷诺数下刚性滑行阻力可比主动游动小 4×；C-bend 越深越快，峰值速度来得越早 | 给出「burst–coast」的可测指标与理论收益 |
| CPG 文献（Hopf / Kuramoto / Matsuoka 链；Ijspeert 系列） | 每关节一个**独立振子状态**；相邻耦合使**相位差/波形涌现**；`ω`、`ε`、偏置 `b_i` 可在线改且**过渡天然平滑**（limit cycle 抗扰）；偏置实现转向 | 给出「真 CPG」的四条判据与可落地方程组，见 §4.5 |
| Glenn Fiedler, *Fix Your Timestep!* + HTML5 Canvas 固定步长实践（两处二手来源引用，未直接访问 Gaffer 原文） | 固定步长 + 累加器 + `alpha` 插值，模拟与渲染解耦；帧尖峰要 clamp 防死亡螺旋 | 本项目 `loop()` 缺的就是这三件 |

### 3.2 工程实现案例

#### 3.2.0 先看本项目的直接参考实现（最贴身、也最刺眼的对标）

11-11 已解析过的 Lively 壁纸「锦鲤池 Koi Pond」（Workshop `3807744786`，核心 `js/koi.js` / `js/main.js`）。本轮 `c9cc80e` 的提交说明就叫「渲染层观感对齐参考实现」，所以必须先核对**到底对齐了什么**：

| 维度 | 参考实现 | 本项目 |
| --- | --- | --- |
| **身体来源** | **独立跟随链**：`px[k] = px[k-1] - segLen·dir` + 相邻关节 17° 帽 → 航向速率与体曲率是**两个独立约束** | 身体 = 头部轨迹的弧长重采样 → 二者共用同一曲率，逼出「最小转弯半径 + turnCum + 不倒车 carving」一整套补丁，并自认「快与不卷环互相制约」 |
| **时间基** | `dt = min(0.05, gap/1000)`；相位累积 `next = max(next+iv, now - iv*0.5)`；`watchQuality()` 自适应降内部分辨率；空闲 30fps / 交互 60fps，掉帧被 dt 吸收 | 硬 30fps、丢帧不补、相位不累积 |
| **摆频随体型** | `(3.2 + 0.1v)·√(60/L)` rad/s，即 `f ∝ 1/√L`；实测 L=70 时 0.91Hz、`c/U≈1.6`，L=140 时 `c/U≈1.8`（**漂移仅 ±13%**） | 摆频与 L 无关 → 大鱼 `c/U≈3`（§4 P1-1）。**参考实现已有现成解法，不必自己发明** |
| **行波 / 幅值** | `sin(phase − k·0.62)` → λ≈0.79L（身上约 1 个波长）；幅值 `∝(u^1.4+0.05)` 头几乎不摆 | `WAVE_SPAN 4.5` → λ≈1.4L；`t²` 包络让前 60% 几乎不动 |
| **群体** | 邻居 2.4L / 分离 0.9L，sep 2.2、ali 0.28、**coh 0.12**；漫游用**共享**随机游走向量 `wOff`，另有**共享鱼食吸引子** | 无 cohesion、每条鱼私有锚点、无任何共享刺激源 |
| **深度 / 次级运动** | z∈[0,1] 一个标量驱动绘制排序、alpha、水色覆盖、影子偏移；尾鳍相位滞后身体 0.9rad；胸鳍摆幅 `∝(1.3 − v/2cruise)`（快游收鳍） | depth 基本只影响绘制顺序/色调；`sk.flap` 只跟 `swimPhase` |

> **这一节的结论**：本轮只对齐了**静态外观**（体型 6.5:1→5.2:1、两段红斑、鳍提亮、描边开口），**没有对齐运动架构**。而观感门槛是随细节上升的——更清楚、更硬、更高对比的鱼，会把 30fps 步进、全身同步变形、匀速抖尾全部放大。这就是「照着参考改，反而更差」的直接解释。它同时说明：本项目「转向快 ↔ 不卷环」的两难**不是物理必然，是路径架构的副产物**。

#### 3.2.1 开源与游戏案例

| 案例 | 技术栈 / 规模 | 核心机制 | 值得抄的一点 | 与本项目的差距 |

### 3.3 三条横向结论

1. **好实现都不靠「更多关节」**：4 个 Rope 控制点、一个 shader uniform、一个速度参数就能成立。复杂度被投在**节奏、时序、群体组织**上，而不是几何约束上。
2. **好实现的时间都是「秒」不是「帧」**：`elapsedTime`、`now/1000`、`dt`。本项目的 `frameCount` / `每帧常量` / `相位不累积` 是异类。
3. **好实现都有「停」**：coast、glide、idle 轨道、每条鱼独立泳姿时序。本项目 `SPEED_FLOOR` + 每帧必推进相位，节律上永远 100% 占空比。

### 4.5 为什么「CPG 重构」没有兑现预期

`CHANGELOG.md` 09-02 调研给出的标准答案是 **CPG 振子链（Ijspeert）**。用外部 CPG 文献的四条判据逐条核对当前实现：

| 判据 | 真 CPG（Hopf/Kuramoto 链） | 当前 `koiSkeleton` | 结果 |
| --- | --- | --- | --- |
| ① 每关节独立振子状态 | 每关节 `(u_i, v_i)` 有自己的相位/幅值 | 35 关节共用一个全局 `k.swimPhase`；`rel[]` 是被钳的关节角，不是振子 | ✗ |
| ② 相邻耦合使波形与相速度涌现 | 旋转矩阵耦合 `p_u/p_v`，相位差由耦合收敛产生 | `r[i] += spineTilt(…)` 直接写解析目标场；无 `rel[i-1]→rel[i]` | ✗ |
| ③ 参数变化由振子拓扑保证平滑 | limit cycle 抗扰，`ω/ε/b` 在线改天然平滑 | 靠跟随层「一阶滞后 + 角速度限幅」事后抹平 | ✗ |
| ④ 体态反馈推进 | CPG 输出驱动关节 → 产生推力/航向 → 传感反馈 | 开环：路径层决定头部，体态不回写运动 | ✗ |

准确命名仍是 **「有状态脊柱 + 解析行波目标场」**（CPG-inspired），不是 CPG。阶段路线核对：

- 阶段 1「路径/体态分离 + 状态化脊柱」：**已完成**。
- 阶段 2「drive 偏置沿脊柱传播、路径从体态涌现」：**只做了前半**（C 形弯曲脉冲 `bend[]` 沿链传播），**因果反转没做**。
- 阶段 3「ESCAPE = C-start 脉冲、速度 ∝ 体型」：**未开始**（大鱼 `c/U` 仍超标，见 §4 P1-1）。

更关键的是**这一轮重构的净效果是「加锁」**：

```
关节 cap（头 0° / 上腩 5–10° / 下腹 10–34°）
+ 跟随角速率上限（0.10–0.20 rad/帧）
+ 头段刚性锁定 r[0]
+ 最小转弯半径 dθ ≤ v/R_MIN
+ 持续盘旋 turnCum 放宽
+ wish 与航向夹角 ≤112°（不倒车 carving）
+ SPEED_FLOOR（永不停止）
```

这些机制各自都解决过真实病灶（折断、卷环、抖动、拉长），但合起来的系统比 v0.1.0 **更确定、更可测、也更僵**。工程指标变绿与观感变差并不矛盾：前者衡量「不犯错」，后者要求「有生命」。

## 5. 三个方案（只描述方案，不给实现代码）

| | **Plan A · 最小可逆（推荐先做）** | **Plan B · 因果闭环** | **Plan C · 真 CPG 重构** |
| --- | --- | --- | --- |
| 改动面 | 按 11-11 日志的**精确清单**反向 patch：`koiRender.js`/`koiSkeleton.js` 的观感部分、`koiFish.js` 的 depth/patch、`koiPond.js` 的排序与斑纹调用；**必须保留**鳍占位符去引号、`shot.mjs`、`fishshape` 按 grad 切层、`ONLY_SPECIMEN` 开关与 `koiMath.mixHex`/`koiDebug` 工具。时间基改为固定步长 + 累加器 + 插值（或按参考实现 `dt` + 相位累积 + `watchQuality()` 降载）；斑带开销与 `bodyPoint` 分配优化 | 在 A 之上：身体改**独立跟随链**（航向/体曲率解耦，删掉半径补丁）；摆频 `∝ 1/√L`；引入 burst–coast 与占空比；**加速度**驱动摆频/摆幅（幅频解耦）；姿态先于位移的 C-start 时序；完整三力 Boids + 共享刺激源 | 在 B 之上：每关节 Hopf/Kuramoto 振子、相邻耦合、相位差涌现、偏置控转向、体态反馈推力；路径层降级为「意图」 |
| 是否解决因果倒置 | ✗（但先解决「看不清」） | ✓ | ✓ |
| 是否解决节奏/群体 | 部分（节奏未动） | ✓ | ✓ |
| 可逆性 | 高：反向 patch + 局部循环改动（**不改写已推送历史**） | 中：状态机与运动学重写，需重录全部基准 | 低：架构重写，**现有 6 个探针基准基本作废** |
| 爆炸半径 | 渲染层 + 主循环 | 运动学 + 体态层 + 探针 | 全运行时 + 全部探针 |
| 主要风险 | 反向 patch 需逐文件核对「保留清单」；固定步长会让所有「每帧常量」参数需按秒重新标定，历史数字不可直接比较 | 半径约束与 C-start 时序可能重新引入卷环；需同步重录 turnprobe 基准 | 复杂度再上一层，而 §3.3 已说明「好实现都不靠更多机制」；有过度工程化风险 |
| 预期收益 | 消除卡顿/走样，让后续改进**能被看见** | 出现「甩尾—滑行—再启动」和成群感，接近「灵动」 | 参数在线可变、过渡平滑、瞬态沿链传递 |
| 探针影响 | bench 数字回落；`finshape`/`fishshape` 切层判据需核对 | 多数行为基准需重录 | 全部重录 |

**推荐：A 先行，A 通过用户目测后再决定 B 或 C。** 理由是 P0-1 会吞掉后面所有改动的可见收益：在 30fps 硬边 + 25× 绘制开销下，即使换上真 CPG，用户看到的仍是「一跳一跳的高对比条纹」。用户既有纪律「先做减法再增机制」也指向 A。B 与 C 并非互斥：若 A 之后仍不灵动，B 的性价比高于 C；只有当「参数在线可变 / 相位差涌现」成为明确需求时才值得上 C。

**贯穿纪律**：① 观感结论只认用户目测，禁止用「代码里有某机制」推断「更自然」；② 渲染层改动必须过 `scripts/shot.mjs` 真实截图（Node 沙箱无 `Image`/`clip`）；③ 每改阈值/判据同步重录基准并在 CHANGELOG 标注口径变化；④ 每个阶段单独可回滚。
